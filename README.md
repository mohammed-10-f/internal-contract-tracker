# نظام متابعة العقود — Final

تطبيق داخلي لمتابعة معاملات الموظفين والعقود، مبني على Cloudflare Workers + D1 + Assets.

## المكونات
- `src/worker.js` — API والمنطق وقاعدة البيانات.
- `public/app.js` — الواجهة وتجربة الاستخدام.
- `public/style.css` — التصميم المتجاوب.
- `public/index.html` — واجهة التطبيق.
- `schema.sql` — مخطط D1 الكامل.
- `wrangler.json` — إعداد Worker وD1.

## قبل النشر
1. تأكد من ربط قاعدة D1 الصحيحة في `wrangler.json`.
2. نفّذ النشر من جذر المشروع.
3. عند تشغيل النسخة الجديدة يقوم `ensureSchema()` بترقية الجداول القديمة تلقائياً، ومنها أعمدة الجلسات `login_at` و`last_seen_at`.
4. إذا كانت قاعدة البيانات فارغة استخدم `/api/setup` مرة واحدة لإنشاء مدير النظام.

## الصلاحيات الأساسية
- `view_records` استعراض المعاملات
- `upload_contracts` رفع المعاملات
- `respond_region` إفادة مسؤول الإقليم
- `approve` الاعتماد النهائي
- `reassign_records` سحب وإعادة إسناد
- `delegate_records` التفويض
- `cancel_records` إلغاء المعاملة
- `view_closed` فتح المعاملات المنتهية
- `reactivate_records` إعادة تنشيط المعاملة
- `view_stats` إحصائيات المسؤولين
- `manage_users` إدارة المستخدمين والصلاحيات
- `manage_regions` إدارة الأقاليم
- `view_audit_log` سجل النشاط والأمان
- `export_audit_log` تصدير سجل النشاط

## التفويض
التفويض يُدار من صفحة **المستخدمين والصلاحيات**، وليس من داخل المعاملة كقاعدة أساسية.
عند تفويض مسؤول إقليم:
- تنتقل المعاملات المعلقة الحالية إلى المسؤول الجديد.
- تُوجّه المعاملات الجديدة للمسؤول المفوض إليه أثناء سريان التفويض.
- يظهر أثر التفويض في السجل.
- يمكن إنهاء التفويض وإيقاف القاعدة المستقبلية.

## Excel
زر **تحميل نموذج Excel** ينشئ نموذجاً موحداً، ويضيف قائمة منسدلة للأقاليم النشطة في النظام. الرفع الجماعي يعرض عدد المعاملات التي أضيفت والصفوف التي تعذر رفعها وأسبابها.

## الملاحظات
- جميع التواريخ المعروضة للمستخدم بصيغة `dd/mm/yyyy`.
- التقارير تحمل تاريخ الإصدار الحالي بتوقيت السعودية.
- مدة المعاملة تُحسب من الإنشاء حتى الإغلاق، وتظهر مباشرة في البطاقات والتفاصيل.
- شاشة الإحصائيات مقيدة بالصلاحية، ومسؤول الإقليم يرى بياناته فقط.
